# 独立主网络互联

两个主网络可以通过一个经批准的联系人交换文字，并各自管理内部员工、模型与工作区。每个实例持有一个网络 UUID 和一个 Ed25519 密钥。公开卡包含 UUID 与 Peer ID，私钥保存在实例私有目录。

```mermaid
flowchart LR
  A[团队 A 的协调者] <-->|同机 Unix + Noise| B[团队 B 的协调者]
  A <-->|跨机加密电路| R[Circuit Relay v2 中转]
  R <--> C[团队 C 的协调者]
```

## 接入和选路

1. 管理员在自己的主机运行独立中转，向参与者分发中转地址和公开 Peer ID。每个参与方主动建立出站连接。中转检查发起方和接收方的准入名单。
2. 在双方选择协作后，签发只允许指定接收方使用的邀请。接收方同意，并由签发方批准。联系人绑定远端 UUID、Peer ID 和本次关系编号，别名由本机定义。
3. 员工使用已有的 `send_message(to="node:别名", message="具体请求")`。核心优先尝试同一用户拥有的本机 socket，跨机时使用固定的中转。两种路径上，端点均通过 Noise 验证实际握手身份。中转可观察网络身份、连接时间与流量。
4. 对端离线时调用返回错误，已发送内容丢失回执时返回 `delivery_unknown` 和消息编号。重发前应核对收件记录。任一侧可撤销当前关系。

## 进度与结果

发送方将本地运行、会话和渠道队列项关联到返回票据，票据有效期七天。对端可以多次向同一请求返回文字。原轮仍在运行时，来源通知进入该轮的 hook。原轮已结束时，受限续办在同一会话交付文字。外部节点无需知道收件人、群 ID 或本机运行编号。

默认将外部请求记入本机收件箱。所有者可以自行回复，或显式允许无工具的本地文本模板。运行时、工作区、文件、私聊记忆和运维权限留在所属网络。协议和本机员工共用同一种 `node:` 联系人接口，当前联邦载荷为文字。
